# 考え方と制約 ── なぜこの配色になっているか

`SKILL.md` の要約では足りないとき、または**新しい色を足す／既存の色を変える**ときに読んでください。
判断の材料になった実測値と、実際に踏んだ失敗をそのまま残してあります。

---

## 1. この配色はどこから来たか

コーポレートロゴの配色比を目安にしています。ロゴを画素単位で数えると、
**白が大半を占め、主役の色は要所にだけ、差し色はごくわずか**という構成でした。

| | ロゴでの面積 | 画面での役割 |
|---|---:|---|
| 白 | 73% | ページとパネルの地 |
| 青 | 10% | ヘッダの帯・ボタン・主役の色 |
| 灰 | 7% | 罫線・表ヘッダ・図版の本体 |
| 黄 | 2% | 状態を示す広い面 |
| 赤 | 1% | 異常と危険な操作だけ |

画面でも同じ比率に寄せます。実際に作った画面を色相で数えたところ
**青 8.7% / 黄 2.4% / 赤 0.4%** で、ロゴの比率とほぼ一致しました。

### 配分を測る方法

スクリーンショットを取り、各画素を HSV に変換して色相で分類します。

- 彩度 0.25 未満は「白・灰」として除外する（そうしないと地色が全部数に入る）
- 明度 0.15 未満も除外する
- 青は色相 205〜250°、黄は 40〜65°、赤は 0〜15° と 335〜360°

淡い地色（薄い青みなど）を評価したいときは、彩度の閾値を 0.08 まで下げた数も併せて見ます。
**濃い青と淡い青みは別々に数えないと判断を誤ります**（淡い地を入れた案は
「濃い青 2.1% / 淡含め 15%」で、片方だけ見ると全く違う印象になります）。

## 2. 実測値 ── 各色が使える場所

白地（`#ffffff`）に対するコントラスト比です。**文字は 4.5、線・図形は 3.0** が基準。

| 色 | 白地 | 判定 |
|---|---:|---|
| 青 `#4169e1` | 4.85 | 文字OK。白文字を乗せる帯にもできる |
| 赤 `#d71345` | 5.16 | 文字OK |
| 黄 `#ffd700` | **1.40** | ★文字にも細い線にも使えない |
| 灰 `#a6afb6` | 2.23 | 罫線としてもやや弱い。面か、もっと濃い灰に |

### 黄色を暗くしていくと、どこで使えるようになるか

| 値 | 白地 | 使える用途 |
|---|---:|---|
| `#ffd700` | 1.40 | 面のみ |
| `#d4ae12` | 2.13 | 面のみ |
| `#c09609` | 2.76 | 面のみ |
| `#a8811a` | 3.61 | 線・図形 |
| `#8f7500` | 4.46 | 線・図形（採用） |
| `#7d6600` | 5.57 | 文字（採用） |

**明るい黄と暗い金の2つを持つ**のはこのためです。片方だけにすると、
必ず「ブランドの黄が出せない」か「文字が読めない」のどちらかになります。

### 青の上に何を置けるか

ヘッダを `#4169e1` で塗ったとき、その上に置ける文字色:

| 色 | 帯の上 | 判定 |
|---|---:|---|
| `#ffffff` | 4.85 | OK（これが上限） |
| `#f7f9ff` | 4.60 | OK |
| `#f2f6ff` | 4.48 | ★不足 |
| `#ffd700` | 3.46 | 線・図形ならOK |

つまり**帯の上ではほぼ白しか使えません**。ラベルを少しくすませて階層をつける、
という普通のやり方が使えないので、**文字の大きさと太さ**で差をつけてください。

## 3. 実際に踏んだ失敗

### 失敗1 ── 色を直値で書いていて、テーマが効かなかった

共通CSSに7箇所、色が直接書かれていました。ログの文字色、エラーランプ、
電流バーの起点、ボタンの文字色、線画の光、閾値超過の縁取り、ホバーの被せ。
テーマを切り替えても、そこだけ元の色のまま残りました。

→ **すべてトークン経由にする。** 直値が1つでもあると「テーマで色が変わる」が嘘になります。

### 失敗2 ── 明るい色を細い線に使った

ヘッダの下に青と黄の細い2本線を引きました。黄は白地で 1.40 なので、
**線としては存在感が出ず、意図が伝わらない**見た目になり、不採用になりました。

→ **明るい色は面に使う。** 線にするなら暗い側を用意する。

### 失敗3 ── 地色だけ変えて、文字を放置した

2件とも、変更した直後は気づきませんでした。

- ページ地に青みを入れた → 補助文字が青地の上で **4.18**（`#5a6775` のままだった）
- 行の地を濃い黄にした → その行の番号が黄地の上で **4.14**（主役の青のままだった）

→ **地色とその上の文字はセット。** 片方だけ変えない。

### 失敗4 ── コントラストを間違った相手と比べた

ピル（自前の白い背景を持つ小さなラベル）の文字色を、その外側にある青い帯と
比べてしまい、「1.93 で基準割れ」と誤検出しました。実際にはピル自身の白背景の上に
あるので問題ありませんでした。

→ **親をたどって、透明でない背景が最初に見つかったところと比べる。**

### 失敗5 ── 青を減らしすぎた

「青が多い」と指摘を受けて帯をやめたところ、8.1% → 1.9% まで落ち、
今度は寂しくなりました。**減らす方向にも振れすぎます。**

→ 配分は**数えてから**判断する。見た目の印象だけで足し引きしない。

## 4. トークンの設計方針

### 意味で名前をつける（見た目で名前をつけない）

`--blue` ではなく `--accent`、`--red` ではなく `--ng`。
テーマを変えたとき、青が青でなくなっても名前が嘘にならないようにします。

### 「地」と「その上の文字」を対にして持つ

片方だけ変えられないよう、対になるトークンを用意します。

| 地 | その上の文字 |
|---|---|
| `--header-bg` | `--header-fg` / `--header-label` |
| `--row-accent` | `--row-marker` |
| `--btn` | `--btn-fg` |
| `--panel` | `--fg` / `--mut` |

### 使わないテーマでも値を持たせる

「このテーマでは使わない」機能も `transparent` を入れておきます。
**全テーマが同じトークンを全部持っている**状態を保つと、
1つ抜けたときに既定値が顔を出す事故を防げます。

### 形は色と分ける

角丸・フォント・余白は `at_theme.css` に置き、テーマ側には**色だけ**を書きます。
テーマを増やすときに考えることが減ります。

---

## 5. 新しい色を足すときの手順

1. **意味の名前を決める**（`--accent-2` ではなく `--warn-strong` のように）
2. **置く場所を決める**（文字か、線か、面か）
3. **コントラストを計算する**（文字 4.5 / 線 3.0）
4. 足りなければ**明るい版と暗い版に分ける**
5. **全テーマに追加する**（1つでも欠けると既定値が出る）
6. 最後に**画面全体の配分**を数えて、偏っていないか見る
